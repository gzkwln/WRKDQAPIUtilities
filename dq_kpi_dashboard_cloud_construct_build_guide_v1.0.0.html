Purpose and intended audience

This guide explains how to recreate the DQ KPI Dashboards solution in Syniti Knowledge Platform Cloud Construct using the WRKDQAPIUtilities SQL database. It is written for a builder who understands Cloud Construct but has never seen this dashboard.

Important: The dashboard has one Main Page, one four-tab container, eight current-state grids and six weekly-trend line charts. The build should remain read-only and must not carry project data into the reusable environment.
  • Target WebApp: DQ KPI Dashboards
  • Target datastore/database: WRKDQAPIUtilities
  • Page: Main Page
  • Tabs: System - PM0, System - P00, System - PM0 Trend, System - P00 Trend

Dataset verification before UI construction

  1. Open each dataset in Cloud Construct and preview it.
  2. Confirm the expected columns exist with compatible types.
  3. Check that DQ score fields are numeric, not formatted text.
  4. Check that WeekID sorts chronologically. A sortable key such as YYYY_WW is appropriate.
  5. Check that ErrorCount, OpportunityCount, NumberOfRules and TotalErrorCount are numeric.
  6. Confirm Subject Area and Data Domain Segment values use consistent spelling across parent and child datasets.

Do not continue to the page build when a dataset fails preview or when parent and child key values differ. Parent-child filtering depends on exact value matching.

Configure navigation buttons

The Subject Areas grids contain three toolbar actions: Navigate to Finance, Navigate to BP and Navigate to Materials. Each opens the corresponding SKP Quality Subject Area in a new browser tab.

Important: Treat navigation URLs as environment configuration variables: FINANCE_SUBJECT_AREA_URL, BP_SUBJECT_AREA_URL and MATERIAL_SUBJECT_AREA_URL.

Recommended deployment sequence

  1. Validate SQL schema and empty-table status.
  2. Create/test the internal SKP database connection.
  3. Create and preview all ten datasets.
  4. Create the WebApp shell and read-only security.
  5. Build PM0 Subject Areas and Data Domains; validate the first binding.
  6. Build PM0 Top 5; validate the second binding.
  7. Build PM0 DQ Implementations.
  8. Build the P00 tab by mirroring PM0 with P00 datasets.
  9. Build the PM0 and P00 trend tabs.
  10. Configure destination-specific navigation URLs.
  11. Load controlled test data or execute the approved extraction process.
  12. Run the functional validation below.
  13. Publish as a Custom Dashboard and validate in Report Hub.
